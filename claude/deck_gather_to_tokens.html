1b · What changes when using real data as input

Set data_path to a directory and the synthetic generator is bypassed entirely.
arr = np.load(files[idx]).astype(np.float32)
x   = torch.from_numpy(arr)
# no reshape branch for multi_1d
return normalize(x, mode)
One .npy file = one sample, found by sorted(root.glob("*.npy")).
Note the missing branch. 1d and 2d inputs get reshaped if under-dimensioned; multi_1d does not. The array must already be rank 2 on disk.
32 × 1024 is not hard-coded. num_traces and trace_length are config values — set them to the real data. Only trace_length % patch_size == 0 is enforced.
Checklist before pointing this at real gathers:
  • Fixed shape across every file. All samples must share one shape or the default collate fails when stacking them into (B, A, T). Ragged gathers have to be padded or dropped upstream.
  • Trace count must equal num_traces. A gather with fewer live traces than the rest forces a decision: pad, interpolate, or discard.
  • Time length must equal trace_length and stay divisible by patch_size — assert at patch_embed.py:64.
  • Consistent trace ordering. Row i must mean the same angle or offset in every file, or the angle axis carries no meaning.
  • No headers survive. A bare .npy carries no dt, geometry, or CDP number. Sampling rate must be uniform across the dataset because nothing records it.
  • NaNs and dead traces are not handled. One NaN propagates straight to the loss.

2 · Normalize — jointly, not per trace

Applied per sample at load time, before the model sees anything.
# mode = 'rms'
rms = (x**2).mean().sqrt()
return x / (rms + 1e-6)
x.mean() with no dim= argument reduces over every element of the (32, 1024) sample → one scalar for the whole gather.
This is the deliberate seismic choice in the repo. One scalar for all 32 traces means the near-to-far amplitude ratio is untouched. Per-trace normalization would rescale every trace to the same energy and erase the AVO trend.
Shape is unchanged: (B, 32, 1024) in, (B, 32, 1024) out. Only the values move.

3 · Two paths out of the same gather

Before going into the mechanics: the gather is used twice, in two unrelated ways. Both methods live on the same class, and both take (B, 32, 1024).
forward — a learned nn.Conv2d. Produces what the encoder reads. 16 → 256.
patchify — two reshape calls, zero weights. Produces the reconstruction target for the loss (foundation.py:forward_loss). 16 stays 16.
The conv output is never compared to anything. The loss compares the decoder's prediction against the reshape. forward does not call patchify, and patchify has no parameters to train.
This is why decoder_pred = nn.Linear(decoder_embed_dim, patch_dim) maps back to 16, not to 256.

5 · What one patch actually is

Follow a single trace all the way down. A patch is 16 consecutive time samples on one trace — it never spans two traces.
# one trace (1024,) → (64, 16) # the whole batch — patchify() (B, 32, 1024) reshape ↓ line 81 (B, 32, 64, 16) reshape ↓ line 82 (B, 2048, 16)
Count never changes: 32 × 1024 = 2048 × 16 = 32,768. reshape only re-labels which index reaches which value.
The cut is hard. No overlap, no taper. The wavelet is sliced wherever a 16-sample boundary happens to fall.
Order is destroyed. The transformer sees these rows as an unordered set — nothing says row 11 followed row 10 until position encoding puts it back.

7 · The grid is flattened into one sequence

Picking up exactly where slide 6 ended, at (B, 256, 32, 64). One line of code turns that grid into the list the transformer wants.
A transformer takes a sequence: one axis of tokens, one axis of features. It has no concept of a 2D grid — so the (angle, time) grid has to be unrolled into a line.
k = angle * 64 + time
angle = k // 64
time  = k %  64
Multiplier is time_patches = 64 — every 64 consecutive tokens are one angle/trace.
Token 100 → angle 1, time 36, samples 576–591.
Consecutive tokens are neighbours in time.
Tokens 64 apart are neighbours in angle.
The same arithmetic is rebuilt in foundation.py lines 120–121 as repeat_interleave(tp) and repeat(nt) — that is how RoPE recovers each token's (angle, time) coordinate after the grid is gone.
why this matters for the seismic problem

8 · Nothing has crossed traces yet

Every operation so far — normalize aside — has acted inside a single trace.
  • The conv kernel is (1, 16). Height 1. Token (angle 7, time 21) is computed from 16 numbers on trace 7 only.
  • So the two things that define a gather — how an event's arrival time shifts from trace to trace, and how its amplitude changes with angle — are invisible to the patch embedding. Both are cross-trace relationships, and nothing here looks across traces.
  • The only mechanism that can relate trace 7 to trace 25 is self-attention in the encoder blocks.
  • And attention alone is permutation-equivariant — it cannot tell angle-neighbours from time-neighbours until position encoding supplies the (angle, time) coordinates.
That is the design argument for RoPE here. RoPE encodes relative position on each axis separately. For a gather the physically meaningful quantity is the difference between two angles, not the absolute trace number — so a relative encoding matches the physics better than a learnable absolute one.
